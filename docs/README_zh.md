# Hermes-arbitrage（中文版）

> **用时间买智商，而不是用钱。**

多智能体文献早就证明：普通模型组织好了，能打出远超权重的智商——开源模型
分层协作，在 AlpacaEval 2.0 上以 65.1% 对 57.5% 压过 GPT-4o
（[MoA, arXiv:2406.04692](https://arxiv.org/abs/2406.04692)）；
什么都不改，只是多采样几个 agent，准确率就随任务难度上涨
（[More Agents, arXiv:2402.05120](https://arxiv.org/abs/2402.05120)）。
瓶颈从来不在论文里，在账单上：没人愿意烧两百美元 API 费跟自己辩论。

本地模型移除了价格这个约束。token 约等于零成本，你改花**墙钟时间**——
把反正睡着的八小时，换成按任何合理价格都买不到的智商。这是一笔套利。

账摊开算。前沿模型的"厉害"，未必是智商领先，首先是**资源领先**：Anthropic
官方公告自己写着，用**超过一百万颗 Trainium2 芯片**训练和运行 Claude
（[来源](https://www.anthropic.com/news/anthropic-amazon-compute)）。
多少张卡、多少度电，这笔账算得清。而智商的差距远小于资源的差距——
DeepSeek-V3 官方口径：全程训练 2.788M H800 GPU 小时（不含前期研究与消融），
与领先闭源模型表现相当（[arXiv:2412.19437](https://arxiv.org/abs/2412.19437)）。
H800 正是出口管制的特供版：芯片矮一截，结果同一起跑线。

所以"厉害"拆开是两部分：**资源优势**——可买断、可垄断、可禁售；
**组织优势**——公开发表、免费引用、禁无可禁。前者写在价目表上，后者躺在
arXiv 上。芯片禁售赌的是前者就是全部；文献说不是。本项目走第二条路：
不在资源上追，在组织上赢——多 agent 一晚上接一晚上地干活，把智商赎回来。
谁也没法给"你睡觉的八小时"发出口许可。这个赌注因任务而异：赌的是你已有的
本地模型低上两档，N 层组合之后在你的任务类上胜过单次前沿调用——任务不同，
赌注不同，管道相同。

有意思的是，靠海量资源堆出来的一点领先，很容易让人**得意忘形**。账本上
明明写着百万颗芯片、吉瓦级电力容量，讲出来却成了天赋、使命与人类的前沿：
卖 token 是生意，拯救人类是事业——既然是事业，服务就不该挑客户；
可条款偏偏在挑。于是卡地区、卡 IP、卡身份核验：账号可以在某天早晨被一封
"违反使用政策"的邮件收走，违反了哪一条，邮件通常不写。
**你付出的是钱，对方核验的是护照。**

这条路还有一个安静的优点：**它不设门卫。**没有服务条款，没有地区白名单，
没有人隔着网络读你的证件。模型不认识你是谁，也不问——它只问你今晚派出了
多少个 agent。

孟子早把原理说清了：

> **"以力假仁者霸，霸必有大国。以德行仁者王，王不待大。"** ——《孟子·公孙丑上》

"以力假仁"四个字，翻译过来就是：仗着资源的力，借"拯救人类"的仁。依赖算力
的，永远需要更多算力；靠组织的，从小处也做得起来。

## 工程缺口

前提是整条多智能体工具链都诞生于按 token 计价的时代：进程与任务同生共死、
调用会返回结果、"长任务"指三十秒。隔夜工作流把这三条假设全部击穿。
AutoGen / ChatDev / MetaGPT 解决"谁跟谁说话"，全部假设编排进程活着、调用会
返回。本仓库在它们**之下**，做五件没人做的事：脱管执行、必达回叫、预算钳制、
污染隔离、账本可审计。

**Hermes-arbitrage 修的就是这个**——任务比发起它的会话活得久，干完之后
**发起会话本身**被唤醒：

```
调度会话（常驻，在 serve 内）
   │  调用 peer_dispatch 工具
   ├─→ ① 执行体：systemd-run --user 瞬时 unit（免疫会话清理）
   │      跑 `hermes -p <peer> chat --query-file <任务书> -c <会话>`
   │      产物 → ~/bot_dispatch/<id>/{out.txt,status,meta.json}
   └─→ ② 监视器：后台进程，persist_on_release
          轮询状态，终态退出 → in-gateway push：向发起会话注入新一轮
```

核心发现：唤醒发起会话只能由网关进程自己做——它是唯一持有平台适配器对象
的东西。Telegram 通知、写库、tail 日志，通知的是**人**，或者谁也没通知。

## 模式与最佳实践

完整剧本见 **[modes.md](modes.md)**。速查：

| 模式 | 保证什么 | 什么时候用 | 最佳实践 |
|---|---|---|---|
| `once` | 全新命名会话，零历史 | 调研、取数、开新线 | 任务书自包含——对方一无所知。会话名让工具派生，留句柄日后 `continue` |
| `continue` | 按账本续上**同一个**会话 | 修复轮、追问、多轮迭代 | 复用同一 `topic`（账本按 发起会话+topic+peer 寻址），只发增量。**绝不用它验证对方刚做的事** |
| `review` | 干净上下文 + 反污染锚定句 | 一切验证者角色 | 三问任一命中就用：含"核实/独立判断"？结论进决策？对方有旧结论？给路径，不给摘要 |
| `sync=true` | 阻塞等结果进本轮 | 一次性/CLI 会话 | 嵌套预算自动钳制（父=预算−120s，子=等待−60s），深度 ≤1 |
| `wait=false` | 点火即走自己轮询 | 仅 cron 无头 | 常驻会话一律用默认 watch |

铁律三条：**评审会话永不接力成干活会话**（continue 评审者的那一刻，它就攒起
了你花钱让它免于携带的上下文）；**token 便宜 ≠ 判断免费**（机械活派子代理，
要品味的活派专家 peer）；**任务书写给"聪明、新来、失忆"的读者**——它是唯一接口。

## 证据，以及证据没说的话

| 论文 | 支持 | 注意 |
|---|---|---|
| [MoA 2406.04692](https://arxiv.org/abs/2406.04692) (ICLR'25) | 弱权重+分层结构 ≥ 强权重 | 增益来自结构，不是人头数 |
| [More Agents 2402.05120](https://arxiv.org/abs/2402.05120) | 堆数量换性能，增益 ∝ 难度 | 简单任务增益趋零 |
| [Debate 2305.14325](https://arxiv.org/abs/2305.14325) | 对抗轮次提升事实性——`review` 的理论 | 故意不内置辩论循环：停滞≠收敛 |
| [Scaling Agent Systems 2512.08296](https://arxiv.org/abs/2512.08296) | 协调开销与结构决定天花板 | 雇第五个并行 agent 前读它 |
| [AutoGen](https://arxiv.org/abs/2308.08155)·[ChatDev](https://arxiv.org/abs/2307.07924)·[MetaGPT](https://arxiv.org/abs/2308.00352) | 编排层谱系，本仓库在它们之下 | 都活不过编排进程之死 |

论文支持的是**经济学**；对管道（脱管、回叫、钳制、隔离）**一字未提**——
那部分是零引用工程，六轮对抗审计的记录在 [design.md](design.md)，伤疤也在。

## "可每个 agent 都丢了上下文啊？"

每个读者都会问的问题，值得正面回答。多 agent 变强不靠信息无损传递——靠的是
**损失可工程化**，而且比较对象是真实的单 agent，不是完美的单 agent：

- **单 agent 也在丢，只是丢得看不见。** 长上下文必然退化：Chroma 对 18 个模型
  的实测显示，可靠性随输入增长而下降，远低于标称窗口
  （[Context Rot](https://www.trychroma.com/research/context-rot)）。
  单 agent 丢的是**注意力质量**——无声、不可定位、不可恢复；
  切分协作丢的是**交接带宽**——白纸黑字写在交接里，下一站可以重跑验收判据。
- **真相源是产物，不是对话。** 文件、账本、git——世界才是无损信道，
  对话历史只是缓存。
- **隔离正是价值所在。** 上下文独立=错误分布独立，聚合准确率超过任何成员——
  恰恰因为大家不共享盲点。带着你完整上下文来的评审，继承的是你的叙事，
  他的价值归零。
- **交接是门，不是管。** 每一跳重跑判据。文献记录的真实失效模式不是
  "上下文丢失"，而是**交接文档烂**
  （[Why Do Multi-Agent LLM Systems Fail?, 2503.13657](https://arxiv.org/abs/2503.13657)）
  ——这是"把交接写下来"的理由，不是"别切分"的理由。

诚实边界：状态密集、高度耦合的任务切不开，那种活单 agent 更优。
赌注是条件式的——可分解、接口清晰、每部分可独立验证。管道不变。

## 快速开始

```bash
cp -r plugin/peer-dispatch ~/.hermes/profiles/<dispatcher>/plugins/
cp scripts/bot_dispatch.py ~/.hermes/profiles/<dispatcher>/scripts/
hermes -p <dispatcher> config set plugins.enabled '[peer-dispatch]'
#   并把 peer_dispatch 加进 platform_toolsets.cli —— 见 docs/SETUP.md
systemctl --user restart hermes-serve.service   # gateway 热重载到不了 serve
PEER=<peer-profile> ./smoke_test.sh             # 开新会话验证
```

## 诚实声明

仅 Linux + `systemd --user`；依赖 Hermes 内部件（`gateway/wake.py`、
`persist_on_release` 等，均非稳定 API，不承诺跨版本兼容）；需多路复用网关。
这是**带可运行代码的设计参考**，非官方插件，与 Nous Research 无隶属关系。
可靠性用词刻意：说"默认 watched"，从不说"绝不丢消息"。

## 为什么不用 Bot Mode？

Bot Mode 让 profile 互发消息。本仓库补的是它不做的四件事：活过会话拆除的
执行体、唤醒**发起会话**的完成通知、带预算与 GC 纪律的账本、
`review`/`continue` 的反污染语义。
